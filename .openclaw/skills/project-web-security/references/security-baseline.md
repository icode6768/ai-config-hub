# ai-digital-human-system 安全基线

本基线针对当前仓库技术栈定制（Flask + SQLAlchemy + Vue + 移动混合端）。
请将其作为安全审计与修复的标准检查清单。

## Critical（严重）控制项

### 1) 对象级授权（API1:2023 / IDOR）

检查：
- 验证每个读/改/删端点都基于 `current_user_id` 强制归属或作用域。
- 验证 URL/body 中传入的 ID 不会在缺少服务端权限校验时被直接信任。

修复：
- 在查询层加入对象归属约束。
- 对未授权对象访问统一返回 `403`/`404` 策略。

验证：
- 用两个用户相互篡改对象 ID，确认访问被拒绝。

### 2) 认证与会话完整性（API2:2023）

检查：
- 校验 JWT 声明（`exp`、`nbf`，以及使用场景下的 issuer/audience）。
- 确保登出会使 Token 失效（吊销列表/轮换策略）。
- 识别缺少补偿控制的长生命周期访问 Token。

修复：
- 缩短 access-token 的 TTL。
- 增加 refresh 轮换与吊销机制。
- 对畸形/过期/伪造 Token 进行确定性拒绝。

验证：
- 在登出/刷新后重放旧 Token，预期返回 `401`/`403`。

### 3) 属性级授权与批量赋值（API3:2023）

检查：
- 识别 request JSON 直接绑定 ORM 模型字段的路径。
- 识别低权限用户可写的高敏感权限字段。

修复：
- 引入 DTO/字段白名单更新映射。
- 强制执行逐字段授权校验。

验证：
- 提交含 `role`、`is_admin`、`status`、`parent_id` 等字段的载荷，确认不存在越权变更。

### 4) CORS 与凭证请求

检查：
- 识别“凭证 + 通配符 origin”组合。
- 识别动态回显 origin 与信任 `null` origin 的配置。

修复：
- 对 origin、method、header 使用显式白名单。
- 默认拒绝未批准 origin。

验证：
- 发送 `Origin: https://evil.example`，确认 API 不信任该来源。

### 5) 密钥与日志卫生

检查：
- 在日志与已提交文件中检索 token/password/API key 泄露。
- 确保 debug/堆栈信息不会返回给客户端。

修复：
- 对日志中的敏感值做脱敏。
- 将密钥迁移到环境变量/密钥管理系统并轮换已暴露密钥。

验证：
- 扫描日志与构建产物中的密钥特征串。

### 5.1) 命令执行与文件包含专项

检查：
- 检查 `subprocess`、`os.system`、shell 调用是否有拼接输入。
- 检查动态 include/import、路径拼接与文件读取入口。

修复：
- 统一改为参数化调用，禁用 shell 拼接。
- 对文件路径做基目录约束、白名单、规范化校验。

验证：
- 使用典型拼接符注入样本确认无法触发系统命令执行。
- 使用目录穿越/远程引用样本确认被拒绝。

## High（高）控制项

### 6) 文件上传加固

检查：
- 存在扩展名白名单。
- 存在 MIME/文件签名校验或等效控制。
- 存在文件大小/数量限制。
- 上传内容存储在不可执行的 Web 根目录之外。

修复：
- 文件名规范化并随机化。
- 增加严格类型与大小校验。
- 按风险画像引入恶意文件扫描。

验证：
- 测试双扩展名、非法 MIME、超大文件、路径穿越载荷。

### 7) 资源滥用与限流（API4:2023）

检查：
- 识别登录、OTP、上传、高开销检索/生成端点是否缺少限流。

修复：
- 增加按 IP 与按用户的速率预算。
- 返回 `429` 并提供重试/退避提示。

验证：
- 对关键端点做突发压测，确认能够平滑限流。

### 8) 客户端 Token 与 XSS 面

检查：
- 识别 local storage/session storage 中存放 JWT 的场景。
- 识别 `v-html`、`innerHTML` 与不安全渲染路径。

修复：
- 在可行前提下优先使用加固 Cookie/会话模型。
- 若历史原因仍保留本地存储，则使用短 TTL + 轮换，并加强 XSS 防护。
- 对不安全 HTML 渲染做清洗或移除。

验证：
- 确认不可信 HTML 不会在未清洗情况下流入渲染落点。

### 8.1) 点击劫持与前端安全头专项

检查：
- 检查是否返回 `X-Frame-Options` 或 CSP `frame-ancestors`。

修复：
- 默认 `DENY` 或按业务最小放开。

验证：
- 在第三方 iframe 中嵌入页面应被拒绝。

## Medium（中）控制项

### 9) HTTP/API 基线加固

检查：
- 强制方法白名单（`405`）。
- 强制 content-type 校验（`415`/`406`）。
- 在适用场景下确保安全响应头完整。

修复：
- 增加集中式响应加固中间件/模式。

验证：
- 对不支持的方法和内容类型做模糊测试。

### 10) 安全资产清单与可追踪性

检查：
- 维护端点清单与安全测试映射。
- 将控制项映射到 OWASP API Top 10 / ASVS 分类。

修复：
- 为所有新增鉴权/上传/高风险端点补齐必需安全测试用例。

验证：
- 若缺失必需安全检查，CI 门禁必须失败。

### 10.1) 脆弱组件与依赖完整性专项（A06/A08）

检查：
- 识别高危依赖版本、未锁定版本、来源不明脚本。

修复：
- 升级高危依赖并固定版本范围。
- 对关键构建产物引入签名/校验机制。

验证：
- 依赖扫描结果无高危或有明确豁免记录。
